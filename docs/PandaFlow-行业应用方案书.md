# 熊猫守望 PandaFlow 行业应用方案书

> 2026-09-14 本地初稿 · B 赛道 SP-A 协同调度中枢 · 平台验收待完成

## 01 场景与问题

PandaFlow 面向动物主题文旅场所，研究游客体验与动物福利约束如何共同进入服务流程。参考机构为成都大熊猫繁育研究基地；项目与园区没有合作或授权关系，也没有接入园区内部系统。

固定故事是一组亲子与老人游客，上午计划游览 120 分钟，希望避免台阶并按偏好参观。系统在合成园区图上生成路线；若演示高温、区域关闭或现场高风险事件出现，就调整计划或中断普通游览流程。北门、路线节点、距离与关闭状态均属于合成故事，不应作为实际到园导航。

**公开依据。** 基地的游客须知说明，天气、动物保育或维护会影响区域开放；官方票务及开放时间页面提供预约、证件和时段说明。它们支持“游览要处理多种约束”这一场景背景，不证明园区存在某个内部效率问题。来源 S1-S3 见文末来源页。

**产品假设。** 将分散规则转为可检查的条件，可能减少服务人员遗漏；将拒答、降级和人工升级纳入同一流程，可能提高解释一致性。目前没有工作人员访谈、真实服务基线或经营成效数据，不能填写节省成本或提升满意度的比例。

## 使用者与输出

| 使用者 | 需要完成的事 | 本地原型提供的结果 |
|---|---|---|
| 游客 | 理解演示预约条件、路线与限制 | 字段补充提示、合成路线、风险说明与有来源的科普 |
| 服务人员 | 遇到异常时判断下一步 | P0-P3 演示分诊、负责岗位与未发送的处置草稿 |
| 运营复核者 | 看清本次流程如何得出结论 | Skill 调用、规则命中、来源与执行记录编号 |

## 02 六个 Skill 与编排

| 独立 Skill | 确定性行为 | 验收输出 |
|---|---|---|
| visitor-policy-check | 检查日期、入园时段、预约状态和证件类型 | status、eligible、缺失项与警告 |
| accessible-itinerary-planner | 按预算、无台阶标记、有效禁行集合和偏好规划 | itinerary、时长、未满足偏好 |
| welfare-risk-dispatcher | 合并演示高温与关闭节点约束 | active_avoid_nodes、重规划要求 |
| panda-knowledge-guard | 查询主食、伪拇指、进食时间三张中英文卡 | 已登记科普答案、来源或明确拒答 |
| incident-triage-dispatch | 用有限关键词规则优先识别人身高风险 | 优先级、人工升级动作、sent=false |
| operations-review | 只聚合白名单执行元数据 | 计数、观察、证据编号，不推断因果 |

总控负责调用以上六个独立 Skill，不计作第七个 Skill。当前没有接入语言模型；输入理解和业务决策以既有结构化字段、关键词和确定性规则为限。

## 三条核心链路

**正常链路：** 预约条件核验 → 初始路线 → 风险检查 → 最终硬约束复验 → 可选知识 → 元数据复盘。可选知识没有依据时返回 needs_input，已经通过检查的路线仍可保留。

**风险改线：** 先把关闭节点和高温相关室外节点合并为完整禁行集合，再重规划并复验最终路线。不能只检查第一条路线，也不能让关闭规则掩盖高温约束。

**高风险中断：** 如输入包含医疗或走失等高风险信号，先分诊并停止普通路线流程；票务诉求、位置缺失或“已处理”的描述不能冲淡风险。升级只生成草稿，不通知任何真实岗位。

优先顺序是人身安全、动物福利与园区规则、无障碍、游览偏好。优先级控制是原型行为，不代表经过园方批准的业务 SOP。

## 03 技术与部署设计

Python 3.11 及以上、FastAPI、Pydantic 组成服务；核心规则使用版本化 JSON，HTTP 只承担校验和适配。六个 Skill 和总控各有精确 OpenAPI 响应模型。统一返回 status、data、rule_refs、source_refs、warnings、next_actions 以及 demo_data 等字段。

公网 Web Demo：https://pandeflow.yikuaibanz.cn/demo，提供四个固定场景；2026-09-14 HTTPS 烟测通过。/health 用于进程存活检查，/ready 检查规则与页面资源是否完整。wheel 随包携带 9 个 JSON 资源、6 份 Skill 文档及 4 个 Web 文件，安装后不依赖原仓库路径。

**天气来源。** Open-Meteo 适配器读取固定位置的模型天气数据，检查体积、单位、时区、有限值与时间。超过项目设定的 30 分钟年龄窗、超过 5 分钟未来偏移或请求失败时，使用明确标记为 demo_data=true 的固定合成回退。该窗口是项目设计；天气不等于场馆实测温度、动物健康或实际开放状态。来源 S5-S6 见文末。

**平台接入。** 已确认的路线是 WorkHub 可视化 API 节点调用现有 HTTPS 服务。先联调 visitor-policy-check 正常请求与缺时段请求，再接入其余 Skill 和三条编排链路。总控 API 成功不能替代六个独立 Skill 的平台触发证据。

## 当前边界与风险

| 边界 | 对结果的实际影响 |
|---|---|
| 只核验演示预约字段 | 未实现全部年龄/身高例外、身份与季节规则；eligible 不是真实入园许可 |
| 合成图与贪心路线 | 不保证全局最优，未验证坡度、地面、排队、出园时间或真实轮椅可达性 |
| 有限天气规则 | 目前温度与合成关闭改变路线，其他天气字段及客流值只展示 |
| 有限关键词分诊 | 不代表自然语言全理解，不提供诊断或治疗，不发送真实工单 |
| 三张登记知识卡 | 只回答受支持的物种科普，实时个体位置、状态和无来源问题拒答 |
| 平台尚未联调 | HTTPS 已验；真实字段、导出 ZIP、能力超市和平台认可的 Live Demo 仍待证据 |

## 04 验证与业务评估

2026-09-14 在本地运行全量 Python 测试，新增知识卡后为 146 项通过；本轮未以此推断平台或比赛交付完成。知识扩充遵循失败用例先行，四条新主题中英文用例在增加卡片前失败，补齐资源后通过，并验证所有登记检索词的双语答案与来源引用。

既有审查曾发现最终路线重新引入禁行、高风险混合描述漏判和天气时效等问题。修复后的反例脚本与限定输入集合属于本地回归证据，不能扩展为真实园区所有场景安全正确。最新执行结果统一记录在 evidence/submission-materials-test-report.md；历史原始证据保留作前后对照。

## 待实施的业务实验

以同一组模拟咨询案例比较人工查阅公开页面与 PandaFlow 输出，记录完成时间、事实错误、遗漏约束和需要升级的事件。案例应覆盖正常游览、高温叠加关闭、缺字段、无依据科普、混合高风险诉求和天气失败。人工与系统顺序交替，事先确定评分标准，保留逐案例记录。

当前尚无参与者和测量结果。完成时间差、错误率、样本量和满意度均应留待实测；不把测试覆盖率转成业务效率改善比例。可用性试验优先邀请有文旅服务经验的人员，验证他们是否理解“演示规则通过”和“人工升级未发送”。

## 交付与落地步骤

第一阶段已形成可安装工程、四场景公网 Demo、API 文档初版和演示脚本。HTTPS 已于 2026-09-14 部署；第二阶段需要平台账户，逐个 Skill 保存真实调用、返回状态和重新导入证据。第三阶段完成能力超市上架、公开代码同步、材料最终回填与 MP4，复核所有公开链接后再提交。

后续若有真实机构试点，需要取得授权的规则来源、可用地图、岗位流程、变更机制与数据边界，重新验证全部硬约束。潜在模式是规则配置与维护服务，但本项目没有客户合同、收入或商业效果证据。
