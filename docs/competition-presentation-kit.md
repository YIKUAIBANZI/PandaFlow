## 一、作品简介（提交框版本）

## 二、一句话定位

**当游客偏好与安全、动物福利或无障碍约束冲突时，PandaFlow 让六个 Skill 按优先级协同，而不是各自给出互相打架的答案。**

## 四、录制前准备

1. 使用最终公开版本启动服务，打开 `/ready`，确认返回 `{"status":"ready"}`。
2. 打开 `/demo`，浏览器缩放设为 100%，关闭书签栏、通知和无关标签页。
3. 预先运行一次四个固定场景，确认当天网络下 `live_current_weather` 是实时成功还是诚实降级；旁白使用对应分支，不临场冒充实时。
4. 清空可能出现姓名、手机号、账号、Token、Cookie、终端路径和通知的画面。
5. 录制分辨率建议 1920×1080，鼠标移动放慢；每次点击后停留 1–2 秒，让评委看清状态、路线和证据。
6. WorkHub 页面只在真实联调完成且已脱敏时录制；当前版本使用本地 Demo 与接入图，不展示或口播不存在的平台成功状态。

## 五、4 分 40 秒完整演示脚本

### 00:00–00:20｜问题与答案

**画面**：PandaFlow 首页首屏，停留在标题和四级优先级。

**操作**：不点击，鼠标依次指向“人身安全”“动物福利与园区规则”“无障碍”“游览偏好”。

**旁白**：

> 大型动物主题景区的路线推荐，不只是把热门景点排成一条线。预约、时间、老人通行、天气、动物福利和现场安全会同时改变答案。PandaFlow 用六个可独立触发的 Skill，把这些约束放进同一条可追溯流程。

**证据点**：首页显示四级优先级；画面保留 `Prototype`、`Demo Data`、`No Real Dispatch`。

### 00:20–00:45｜真实性边界

**画面**：首屏真实性标签和页脚边界。

**操作**：轻微向下滚动，再回到场景选择区。

**旁白**：

> 这是参赛原型，不是园区官方系统。园区图、客流和部分规则是演示数据；系统不收集证件号码，不诊断，不发送真实工单，也不把天气推断成动物个体状态。每次响应会保留 `source_refs`、`rule_refs` 和 `demo_data`。

**证据点**：真实性标签、页脚声明、右侧“证据标本柜”。

### 00:45–01:40｜常规流程：六类能力进入同一记录

**场景 ID**：`normal_all_skills`

**画面**：选择“常规游览、失物咨询、科普和复盘”，运行后展示主展台与证据柜。

**操作**：点击场景、点击“运行所选场景”；依次指向 75 分钟路线、失物草稿、科普回答、调用链和复盘计数。

**旁白**：

> 先看常规场景。一家亲子游客带老人从北门进入，系统完成入园字段核验，再生成无台阶、120 分钟预算内的路线。失物咨询由事件 Skill 生成 P3 人工核实草稿，画面明确显示 `sent=false`；科普回答只来自登记知识卡。最后，复盘 Skill 只汇总脱敏元数据，不读取事件原文，也不宣称问题已经解决。

**Skill 证据**：

- `visitor-policy-check`：检查日期、上午时段、预约状态和证件类型字段。
- `accessible-itinerary-planner`：显示逐站到达、停留和总时长。
- `welfare-risk-dispatcher`：在常温场景返回低风险并保持初始路线。
- `panda-knowledge-guard`：回答饮食问题并返回来源。
- `incident-triage-dispatch`：输出失物类别、P3 与未发送草稿。
- `operations-review`：汇总实际调用、状态、规则和记录编号。

### 01:40–02:25｜动态改线：偏好让位于动物福利

**场景 ID**：`heat_replan`

**画面**：切换“合成高温触发避开竹林并复盘”。

**操作**：运行后左右对比初始路线和最终路线，指向“为安全已避开”、天气来源和两次路线调用。

**旁白**：

> 现在把演示温度提高到 33 摄氏度。`welfare-risk-dispatcher` 命中高温室外节点规则，要求重新规划。初始路线包含竹林步道，最终路线从 77 分钟调整为 47 分钟，并明确列出被省略的偏好。关键点不是推荐变短，而是全部活动禁行节点进入硬约束，第二次规划不能把风险节点偷偷加回来。

**证据点**：`replanned=true`、竹林从最终路线移除、`active_avoid_nodes`、路线 Skill 在调用链出现两次。

### 02:25–03:05｜高风险中断：安全先于完整流程

**场景 ID**：`human_escalation`

**画面**：切换“走失事件阻断普通规划并转人工”。

**操作**：运行后停留在 `escalated`、P1、立即动作和未执行范围。

**旁白**：

> 如果输入变成儿童走失，系统不会为了展示完整 Demo 继续规划路线。事件分诊返回 `escalated` 和 P1，普通入园、天气与路线步骤立即停止，只保留转人工动作和未发送草稿。复盘记录的是实际执行过的一次分诊，不会把高风险状态覆盖成普通成功。

**证据点**：没有最终路线；显示高风险状态、P1、立即动作与 `sent=false`；不回显事件自由文本。

### 03:05–03:40｜真实工具与诚实降级

**场景 ID**：`live_current_weather`

**画面**：运行“当天实时天气”。

**操作**：指向温度、体感、降水、天气代码、风速、观测时间、抓取时间和署名；若网络失败，改为指向 `degraded` 与 `fixed_fallback`。

**实时成功旁白**：

> 这一场景主动调用 Open-Meteo，校验单位、时区和观测时效，再把天气交给既有风险规则。天气是公开网格条件，不代表园区实时运营或动物健康。

**网络降级旁白**：

> 当前网络调用失败，系统没有伪造实时结果，而是返回 `degraded` 和明确标记的固定演示快照。安全改线仍可复现，但画面不会把它写成实时天气。

**证据点**：实时分支显示 Open-Meteo 署名和时间；降级分支显示来源与警告，两者只能按真实运行结果择一口播。

### 03:40–04:15｜架构、WorkHub 路线与当前边界

**画面**：切换到六 Skill 目录/API 文档或一张接入拓扑图；不要展示账号和密钥。

**操作**：依次高亮六个 Skill 名称与总控；展示统一响应字段。

**旁白**：

> 六个 Skill 都有独立 `SKILL.md`、Python 逻辑、HTTP 契约、资源和测试：`visitor-policy-check`、`accessible-itinerary-planner`、`panda-knowledge-guard`、`welfare-risk-dispatcher`、`incident-triage-dispatch`、`operations-review`。总控只负责按状态编排，不冒充第七个 Skill。WorkHub 将采用 API 调用节点连接这套服务；**WorkHub 尚未完成真实联调**，因此当前画面只证明本地闭环和接入准备。

**证据点**：六个目录、统一 `status/request_id/source_refs/rule_refs/demo_data`，以及 API 文档中的未完成边界。

### 04:15–04:40｜验证结果与收束

**画面**：测试摘要、API PDF 封面，最后回到 PandaFlow 首页。

**操作**：展示最终冻结版本的测试输出；当前材料稿对应 137 项 Python 与 8 项前端测试，正式录制必须以当时实跑数字替换。

**旁白**：

> 当前本地版本通过 137 项 Python 和 8 项前端测试，覆盖正常、边界、异常以及 156 组限定高温路线组合。PandaFlow 不试图替代工作人员，而是让每次自动化决定都知道什么时候继续、什么时候降级、什么时候必须停下来交给人。

**证据点**：测试命令、退出码、API PDF 版本；不要只展示手写数字或历史截图。

## 七、录制证据位

## 九、正式成片验收

- 时长 `≤ 05:00`，建议控制在 `04:35–04:50`。
- 字幕与旁白一致，关键状态码、数据来源和免责声明可读。
- 四场景均来自当次运行；网络降级则按降级脚本口播。
